# PART A — PS1: ADAPTIVE LEARNING ENGINE

## A1. Student learning workflow

Implement a working learning journey:

1. Student selects a subject.
2. Student selects a topic.
3. System presents a quiz.
4. Student submits answers.
5. Backend evaluates correctness.
6. System updates topic mastery.
7. System selects the next question difficulty.
8. Student sees progress and weak concepts.
9. Student receives remedial explanations and practice questions.

## A2. Knowledge and mastery tracking

Create a concept/topic structure.

Each topic should have:
- topic_id
- subject_id
- topic_name
- description
- prerequisite_topics where applicable

Track student mastery for each topic:
- student_id
- topic_id
- mastery_score
- questions_attempted
- correct_answers
- last_attempted_at

Mastery must update after each quiz attempt.

Use a transparent mastery update algorithm. Document the formula and ensure scores remain between 0 and 100.

Create a visual topic mastery meter and concept relationship graph.

## A3. Adaptive quiz engine

Implement three difficulty levels:
- Easy
- Medium
- Hard

Use performance-based rules to select the next question difficulty.

Example:
- Consistent correct answers: increase difficulty.
- Mixed performance: maintain difficulty.
- Repeated incorrect answers: decrease difficulty and identify weak concepts.

Use actual quiz results, not random difficulty changes.

Create a question bank with meaningful sample questions.

Each question must have:
- question_id
- topic_id
- question_text
- difficulty
- options where applicable
- correct_answer
- explanation

Validate generated questions before adding them to the question bank. If an LLM is unavailable, use the question bank.

## A4. Remedial learning

When a student struggles with a topic:
- Identify the weak concept.
- Show a simplified explanation.
- Provide a worked example where appropriate.
- Recommend practice questions.
- Save remediation history.

Use curriculum-grounded content. Do not invent textbook citations or pretend that an uploaded textbook was indexed if it was not.

## A5. PS1 teacher dashboard

Implement:
- Classroom mastery overview.
- Average performance per topic.
- Weakest concepts.
- Students needing additional support.
- Recommended remedial topics.

# PART B — PS2: AUTOMATED ANSWER EVALUATION ENGINE

## B1. Faculty assessment creation

Implement:
- Create assessment.
- Add questions.
- Set maximum marks.
- Enter reference answers.
- Add rubric criteria and marks.
- Validate that rubric marks sum to question maximum marks.

## B2. Submission processing

Support:
- Digital PDF uploads.
- TXT uploads.
- Multiple student submissions.
- Student ID association.

Use PyMuPDF for digital PDF extraction.

For scanned documents:
- Detect when extracted text is empty or insufficient.
- Return a clear message that OCR is needed.
- Do not silently grade empty extracted text.

Prepare the service interface for OCR integration in Phase 3.

Display extracted text for review.

## B3. Semantic grading

Implement a hybrid grading engine.

Use:
- Sentence Transformers for semantic comparison where available.
- Rubric-based concept coverage.
- Explicit correctness checks where possible.
- Transparent partial-credit rules.

For each criterion, calculate:
- Marks awarded.
- Maximum marks.
- Evidence from the student answer.
- Reason for awarding or withholding marks.

Do not use raw cosine similarity as the final marks calculation.

Do not let an LLM independently invent marks. The grading engine must enforce rubric limits and score constraints.

If the embedding model is unavailable, implement a documented fallback so the workflow remains functional.

## B4. Feedback generation

Generate structured feedback with:
- Correct concepts.
- Missing concepts.
- Incorrect concepts.
- Improvement suggestions.

Use an LLM only to express structured grading findings in readable language.

Provide a deterministic feedback fallback.

## B5. Faculty moderation

Implement:
- Evaluation result review.
- Score override.
- Moderation reason.
- Original AI score preservation.
- Final score storage.
- Reviewer identity.
- Timestamp.
- Audit history.

Faculty must be able to approve, edit or reject AI-suggested results.

## B6. Student results

Display:
- Assessment name.
- Marks awarded.
- Maximum marks.
- Criterion-wise scoring.
- Feedback.
- Evaluation status.

# PART C — PS3: DROPOUT PREDICTION ENGINE

## C1. Data ingestion

Implement CSV upload and validation.

Support documented fields such as:
- student_id
- attendance_rate
- average_grade
- late_assignments
- missing_assignments
- lms_logins_30d
- engagement_change_pct
- previous_failure_count
- dropout_label (training dataset only)

Validate:
- Required columns.
- Missing student IDs.
- Duplicate records.
- Invalid percentages.
- Negative counts.
- Missing values.
- Invalid target labels.

Show accepted and rejected row counts.

## C2. ML pipeline

Implement a scikit-learn Random Forest baseline classifier.

Requirements:
- Preprocessing pipeline.
- Missing-value handling.
- Train/test split.
- Stratification where appropriate.
- Leakage prevention.
- Probability prediction.
- Saved model and preprocessing pipeline.

Keep training labels separate from prediction-time input fields.

If no real historical data exists, create clearly labelled synthetic demo data.

Do not present synthetic data performance as real-world prediction accuracy.

## C3. Evaluation metrics

Calculate and expose:
- Precision.
- Recall.
- F1-score.
- ROC-AUC when valid.
- Confusion matrix.

Show class distribution and test-set size.

Do not hide poor model performance.

## C4. Risk classification

Generate:
- risk_probability
- risk_level
- model_version
- prediction_timestamp
- student_id

Use configurable low/medium/high thresholds.

Clearly identify provisional demo thresholds if they have not been institutionally validated.

## C5. Explainability

Provide understandable explanations for each prediction.

If SHAP can be integrated reliably, use it.

Otherwise, implement transparent feature summaries and label them as rule-based indicators, not SHAP explanations.

Do not claim that contributing features cause dropout.

## C6. Retention intervention engine

Create recommendations based on observable indicators.

Examples:
- Low attendance: faculty check-in.
- Multiple missing assignments: academic planning support.
- Declining grades: subject tutoring.
- Reduced LMS activity: engagement/access check-in.

Implement:
- Create intervention.
- Assign counselor.
- Set priority and due date.
- Update status.
- Add counselor notes.
- Complete or dismiss intervention.

All recommendations must be reviewed by a human.
