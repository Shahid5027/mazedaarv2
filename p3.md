# PART A — PS1: MULTILINGUAL ADAPTIVE LEARNING

### A1. Multilingual voice input

Implement speech-to-text for at least:
- Kannada
- Hindi

The student must be able to speak a question or query and see the recognized text.

Use an appropriate browser speech API or an available speech recognition service. Handle unsupported browsers and unavailable microphones gracefully.

Do not pretend speech recognition is working when it is unavailable.

### A2. Text-to-speech explanations

Implement spoken explanations in Kannada and Hindi.

The student must be able to:
- Select a language.
- Read the explanation.
- Play the explanation as audio.
- Pause or stop playback where supported.

Use a reliable browser TTS implementation or an available service.

Clearly indicate when a fallback voice is being used.

### A3. Interactive knowledge graph

Upgrade the existing SVG knowledge graph into an interactive graph.

Requirements:
- Display concepts and prerequisite relationships.
- Display mastery per concept.
- Show weak and mastered concepts.
- Allow students to select a concept.
- Show associated lessons and quizzes.
- Update graph state when mastery changes.

Use Cytoscape.js, D3 or another appropriate lightweight library.

### A4. Curriculum-grounded remediation

Implement a basic RAG pipeline if suitable curriculum documents are available.

Requirements:
- Support uploading curriculum PDFs.
- Extract and chunk text.
- Retrieve relevant chunks for a weak topic.
- Generate explanations based on retrieved material.
- Show source document/page references when available.
- Generate targeted practice questions.

If no LLM or vector service is available, provide a clear deterministic fallback.

Never fabricate textbook references.

### A5. Offline and low-bandwidth support

Implement:
- Local caching of recently accessed learning content.
- Cached question data.
- Graceful offline messaging.
- Retry/synchronization when connection returns.
- Avoid unnecessarily large API payloads.

### A6. PS1 performance report

Measure actual response latency for:
- Quiz retrieval.
- Quiz submission.
- Mastery update.
- Remedial explanation generation.
- Voice-related requests where applicable.

Calculate average latency from actual measured runs.

Report whether the average is below the official 8-second target. Do not invent performance numbers.

# PART B — PS2: SEMANTIC GRADING AND OCR

### B1. Semantic embeddings

Implement actual Sentence Transformer embeddings.

Preferred initial model:
- all-MiniLM-L6-v2

Use a local model where possible.

Implement:
- Reference answer embeddings.
- Student answer embeddings.
- Criterion-level semantic similarity.
- Concept coverage.
- Evidence extraction.
- Contradiction or incorrect-concept checks.

Do not equate high cosine similarity with correctness.

If model downloads are unavailable, provide a clear fallback and report the limitation.

### B2. Improve grading logic

Combine:
- Semantic similarity.
- Rubric criteria.
- Concept coverage.
- Technical correctness checks.
- Partial-credit rules.
- Evidence from student answers.

Each criterion must return:
- Maximum marks.
- Awarded marks.
- Similarity or matching information.
- Supporting evidence.
- Missing concepts.
- Incorrect concepts.
- Reason for the score.

All scores must remain within rubric limits.

### B3. OCR for scanned documents

Implement scanned PDF and image processing.

Use:
- PaddleOCR or Tesseract.
- PyMuPDF for PDF processing.
- OpenCV for preprocessing if necessary.

Support:
- Digital PDFs.
- Scanned PDFs.
- Image submissions.

Requirements:
- Detect scanned pages.
- Convert PDF pages to images.
- Apply OCR.
- Preserve page references.
- Show extracted text for faculty review.
- Flag low-confidence or unreadable text.

Do not silently grade unreadable submissions.

Handwriting recognition should be tested on actual sample documents. Do not claim handwritten OCR support solely because printed OCR works.

### B4. Human-grade benchmark

Expand the existing PS2 benchmark.

Use a documented human-graded dataset.

Report:
- MAE.
- Criterion-level MAE.
- Score agreement.
- Strong, partial and weak answer performance.
- Semantic equivalence examples.
- Cases where the model fails.

Preserve the Phase 2.1 benchmark results so performance changes can be compared.

Do not manipulate reference marks to improve metrics.
